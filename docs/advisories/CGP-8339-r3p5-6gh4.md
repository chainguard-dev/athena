# CGP-8339-r3p5-6gh4

Webserver.doReply() allows reading arbitrary files via a double-slash HTTP request that bypasses the docroot containment check.

## Severity

- **CVSS_V3:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N`

## Details

### Root Cause

`Webserver.doReply()` at line ~285 of `src/main/javassist/tools/web/Webserver.java` extracts the URL path:

```java
filename = urlName = cmd.substring(5, cmd.indexOf(' ', 5));
```

For a request `GET //etc/passwd HTTP/1.0`, `cmd.substring(5)` yields `/etc/passwd`. The `checkFilename` method checks for `..` sequences but does not reject paths starting with `/`. When `htmlfileBase` is null, `new File("/etc/passwd")` is an absolute path and `file.canRead()` succeeds on most Unix systems, causing the file to be served to the client. The `getResourceAsStream` fallback further exposes classpath resources.

### Affected Locations

- `src/main/javassist/tools/web/Webserver.java`, line 285 — `doReply(InputStream,OutputStream,String)`: absolute-path bypass via double-slash request.

### Attack Vectors

- **Double-slash absolute path traversal**: An attacker sends `GET //etc/passwd HTTP/1.0` to the Webserver. The `GET /` prefix stripping leaves `/etc/passwd` as the filename, which is served directly.
- **Classpath resource exposure via getResourceAsStream fallback**: If the file is not found on disk, the fallback `Class.getResourceAsStream("/" + urlName)` may expose `.class` files or configuration resources from the classpath.

### Impact

Arbitrary file read from the server filesystem (any file readable by the JVM process) for any application that starts `Webserver`. The server binds to all interfaces by default and requires no authentication.
